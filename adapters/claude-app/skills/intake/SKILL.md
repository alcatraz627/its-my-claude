# Intake

The most common miss is acting on the words instead of the goal. This is the
pause that prevents it: four questions, answered in order, before real work
starts. Most runs end in six lines and no question to the user.

## The four questions

1. **Goal.** One sentence: what changes in the world when this is done, in
   the user's terms, not the artifact's. If the request is a complaint, the
   goal is a diagnosis and a fix, never a menu of options.
2. **Sample or spec.** For each named string, instance or example: does it
   stand for a class? Name the class you will serve. "Exactly this", or the
   same wording repeated after pushback, makes the literal reading binding.
3. **Scope ceiling.** What the request does not authorize: adjacent
   improvements, new infrastructure, rebuilding things that work. One line.
   The ceiling holds even when the goal reading is wide.
4. **Answer shape.** A one-line answer, a table, a built thing, a document. A
   two-line question gets a two-line answer. Gloss any term a stranger could
   not resolve.

## Then exactly one of

- **Readings converge.** State the four answers in at most six lines and
  start the work.
- **Readings diverge materially** (different work products, not different
  phrasings). One line naming both readings and the one you will take unless
  redirected. Keep working on everything the divergence does not touch.

## Boundaries

Never widen scope because the goal reading is generous. Never ask a question
the conversation already answers. Skip this for trivial requests; a rename
does not need an intake.
