# Decision bundle

The user's attention is the scarce resource, so every question handed to them
arrives already answered: context, options and your recommendation in one
pass, so a ruling costs one read and one word.

## When to use

- A plan that says "awaiting a decision" or "needs the user"
- Questions piling up while work continues around them
- Two authorities that conflict, such as a written spec and a fresh instruction
- Scope the user has not seen yet, before building it

Not for work you are authorized to do (do it), or a single question with an
obvious default (pick it, say so, move on).

## 1. Investigate until you can falsify your own proposal

- Read what the destination already says before proposing anything for it.
  This routinely kills your own items.
- Search before every "there is no X" claim.
- When a fresh instruction contradicts a written rule, that contradiction is
  itself a question for the bundle. Do not resolve it by picking whichever you
  heard last.
- If nothing in your plan died during this step, you were collecting support,
  not investigating.

## 2. Plan with alternatives

Each open choice gets its real alternatives and your pick, with the reason.
When the plan covers many similar items, build one fully and get it reviewed
before doing the rest.

## 3. Bundle the questions

One message, every open decision. Each one carries:

| Part | Contents |
|---|---|
| Context | Enough that answering needs no other document open. Quote conflicting sources verbatim. |
| Options | The real alternatives, usually two or three, each with its consequence |
| Recommendation | Yours, listed first, with the reason in one sentence |

Number them so the user can reply `1a 2b`, or `ok` to take every
recommendation. Say which items block work and which do not, so the user knows
what a late answer stalls.

## 4. Record the ruling where it binds

Write each ruling into the document or plan it governs, in the user's own
words where the wording carries the constraint. Anything the user did not
answer stays open and named, never quietly adopted as a default.

## 5. Build only what was ruled

A ruling on four questions authorizes four answers, not the adjacent
improvements noticed while waiting. Report back item by item against the
rulings.

## Anti-patterns

- The naked question: "A or B?" with no context and no recommendation
- The drip: five questions across five messages instead of one bundle
- Momentum as permission: a deferred item that a later message brushes
  against is still deferred
- The unrecorded ruling: answered in chat, written nowhere, lost next session
