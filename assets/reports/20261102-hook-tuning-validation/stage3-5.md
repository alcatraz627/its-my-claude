A request or query sent to `*` (broadcast) never gets an awaiting row (router.ts:325 skips `a.to === "*"`), so `aw` is undefined, the digest reports null, and the Stop hook now treats it as "nobody waits" and stops blocking. Before the change a broadcast ask blocked once. Read-only finding, not run against a live broker.

Mutation reasoned from the test imports, not executed on a copy.
3. MEDIUM, `scripts/hooks/stop-arbiter.py:46-54` plus `pr-review-gate.py` `STOP_BUDGET_S = 40`. The old Stop entry gave pr-review-gate `timeout: 60`; the arbiter caps every gate at 30 s (`STOP_ARBITER_TIMEOUT`) and the gate's own budget is 40 s, with `GH_TIMEOUT_S` 10 per call and one `gh` fetch per tracked PR. With 3 or more tracked PRs on a slow GitHub the gate is killed at 30 s before `save(path, st)`, so its block counts and "noted" flags are lost (blocks can repeat past MAX_BLOCKS, notes repeat). The comment at `pr-review-gate.py` ("The Stop entry in settings.json carries a 60 s timeout") is now false. Fix: lower STOP_BUDGET_S to about 20 or give the arbiter a per-gate timeout column.
4. MEDIUM-LOW, arbiter drops output when a gate leaves a background child holding stdout. Repro `scratchpad/v/bg.py` (gate prints a block, then `sleep 20 &`): with `STOP_ARBITER_TIMEOUT=3` the arbiter took 3.0 s and returned `''`; the block was lost. Real gates mostly redirect (atone-stop-gate.sh:111 does, pr-review-gate Popen uses a log file), so latent. `run_gate` could read stdout from a file or kill the process group.
5. LOW, format-gate path advisory leaves a period after the first path when two paths match. Repro `scratchpad/v/fg.py` case two-paths: output `paths, clickable: \`/a/b/c.md\`. ; /x/y/z.py`. `format-gate-stop.sh` strips only the final trailing period (`${s%.}`) after joining, so the first span keeps `.` right after the path, which is the exact clickability defect the line exists to avoid. Strip per span before joining.

Anchor `secret-scan` and `/core-dump` to whole-line patterns or only subtract a bounded number of chars.
