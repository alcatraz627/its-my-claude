# skills-parked — kept, not loaded

Skills the owner ruled out of the live roster (2026-08-20) but explicitly kept:
project-specific packs and zero-use tools that may earn their way back. Nothing in
this directory reaches the session roster, so parked skills cost no description
budget and cannot auto-trigger.

The agent's awareness of this directory is `INDEX.md` (a tldr per skill with tags
and activation criteria, regenerated by `bash ~/.claude/scripts/parked/parked.sh index`)
plus the SessionStart nudge (`scripts/hooks/parked-skills-nudge.sh`), which runs the
owner's two-way check when a project is encountered:

1. Which parked skills match this project (tags vs project markers)? Offer to copy
   one in: `parked.sh copy <name> --to <project>` puts it in the project's own
   `.claude/skills/`, where it loads locally.
2. Is this session's goal lengthy, prompting-heavy, or feedback-heavy in a shape
   seen before? Record it: `parked.sh friction add "<shape>" --project <p>`. On the
   SECOND occurrence of a shape, ask the owner whether to build a skill for it
   (owner ruling: twice, not thrice, to build the repo up).

Un-parking is the owner's call: move the directory back into `~/.claude/skills/`
and rerun `scripts/skills-index.sh`.
