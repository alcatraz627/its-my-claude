# Dev servers — the three-tier port policy

Every local server belongs to exactly one tier, and the tier decides its port
band, its runner, and its lifecycle. The old rule ("everything in pm2, 30xx/50xx")
failed because it had one answer for three different problems; this replaces it
(migration 0029).

| Tier | What it is | Ports | Runner | Lifecycle |
|---|---|---|---|---|
| **1 · mature** | Shared/deployed projects the USER owns (their next apps, 8001 backend) | Whatever the user pins — `ports.sh pin <port> <name>` | Raw terminal, user's hands — NOT pm2 | User-managed; Claude never squats or manages these |
| **2 · local-persistent** | Device-local always-on services (decision-pages, review feedback, data-forge server, transcript servers) | Allocated from **5100–5399** via `ports.sh claim <name> --tier 2` | **pm2** (+ `pm2 save`) — this is the only tier pm2 is for | Persistent until deliberately retired |
| **3 · one-off** | Ephemeral demos, mock dashboards, review pages, scratch servers | Allocated from **6200–6499** via `ports.sh claim <name> --tier 3` — carries a **24h TTL** | Foreground, or background with the claim recorded | Auto-expires; `ports.sh reap` kills expired ones (revivably) |

A port number is a label: `:62xx` reads as "ephemeral Claude thing, killable",
`:51xx` as "local service", anything pinned as "the user's, hands off".

## The ledger — `scripts/dev-servers/ports.sh`

State is an append-only event log at `~/.claude/dev-servers/port-events.jsonl`;
`port-registry.md` beside it is a DERIVED view (regenerated by `scan`, never
hand-edited — the old hand-rotted scratchpad registry is retired).

```
ports.sh scan                 # live listeners vs claims — "what is where"
ports.sh claim <name> --tier 2|3 [--port N] [--ttl-h H]   # prints the port
ports.sh pin <port> <name> [--cwd DIR]                     # tier-1 declaration
ports.sh reap [--dry-run]     # kill expired tier-3 listeners (records revive cmd)
ports.sh revive <name|port>   # bring a reaped one-off back (re-claims, new TTL)
ports.sh next --tier 3        # just print the next free band port
```

**Reap is not deletion.** Every reap records the exact command + cwd, so
`revive` restores it in one step. A claim revived **2+ times is mis-tiered** —
the tool flags it loudly: promote it to tier 2 (pm2 + 51xx) instead of reviving
again.

## Enforcement — `hooks/guard-dev-server-port.sh` (PreToolUse · Bash, BLOCKING)

Nudging didn't bind (user decision 2026-07-10), so dev-server launches are
**blocked** when they: carry no port at all · target a framework default
(3000 3001 4200 5000 5173–5179 8000 8080 8888) · target a pinned tier-1 port ·
target an already-claimed port. Every block message contains the corrected
command with a pre-allocated free port, so compliance is copy-paste. Always
pass `--strictPort` (or the framework equivalent) — silent auto-increment is
how orphan fleets stack.

Escapes: `PORTS_OK=1` command prefix (project config already pins a safe port) ·
`touch ~/.claude/.no-dev-port-gate` (machine-wide until removed). False fires
are reviewable feedback: file them via
`propose.sh add --category hooks --title "guard-dev-server-port false fire…"` —
the hook-telemetry review reads those plus this hook's warn-log records.

**Blocked and unblocking needs the USER** (pinned-port conflict, a mature app
that must move, a policy question)? **Pester them explicitly in your reply** —
state what you need from them and why you're stuck. Never stall silently and
never self-permit around the gate (user directive, 2026-07-10).

## pm2 notes (tier 2 only)

Persistence needs BOTH `pm2 startup` AND `pm2 save`. Name entries after the
claim (`pm2 start npm --name <claim-name> -- run dev -- --port <claimed> --strictPort`).
nginx `.test` domains: `scripts/dev-servers/gen-nginx-conf.sh`. The older
`pm2-register.sh` predates the tier system; prefer `ports.sh claim` + explicit
pm2 start.

## Idle lifecycle: `scripts/dev-servers/svc.sh` (migration 0043)

Anything pm2 runs is stopped after **12 hours with no new connections**, at any
tier. pm2 is the ownership boundary, not the tier: the tier says who owns the
PORT, this says who owns the PROCESS. A server started by hand in a terminal is
never touched, because svc cannot see it.

**Before using any pm2 service, call `svc up <name>`.** It is idempotent, so run
it unconditionally instead of checking first. It starts the app if stopped,
waits for a real listening socket, prints the URL, and marks the service used.
Assuming a service is live is now wrong, because it may have been reaped
overnight.

```
svc status              # what is running, its ports, how long unused
svc up <name>           # start if stopped, wait for its port (call this first)
svc down <name>         # stop now
svc reap --dry-run      # what would be stopped
```

Idle means "no NEW connection", not "nothing connected". A Vite HMR websocket
held by a forgotten browser tab would otherwise read as use forever, which is
the exact failure this replaced. Tuning lives in env vars (`SVC_IDLE_HOURS`,
`SVC_GRACE_MIN`) and `~/.claude/dev-servers/svc-never-reap`.

Reap is not deletion here either. Every reap records `svc up <name>`.

## /doctor

The doctor ports step runs `ports.sh scan` and flags UNTRACKED listeners,
EXPIRED tier-3 claims, and pinned ports with unexpected owners.

## Upgrading this system? Read the architecture doc first

`~/.claude/assets/docs/port-system-architecture.md` — internals (event log +
fold semantics, owner-boundary rules), the invariants that must not break
(allocation mutex, append-only log, lsof-free `check`, fail-open rationale),
the known edges accepted for v1, and the sandbox testing recipe. Everyday
sessions don't need it; anyone touching ports.sh or the guard hook does.
