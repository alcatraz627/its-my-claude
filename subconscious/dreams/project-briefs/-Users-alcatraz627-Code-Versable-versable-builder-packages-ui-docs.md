## What this project is about
UI docs package for a Versable monorepo — maintaining and reviewing documentation surfaces with a pattern of skeptical review, pipeline investigation, and cost-conscious agent orchestration.

## Things to do (or keep doing)
- **State the point first.** Lead with the answer, not the preamble — one plain sentence, then supporting detail.
- **Investigate zero-output stages.** When a pipeline step returns empty, treat it as a misconfigured filter before moving on.
- **Split model tiers across pipeline stages.** Cheap models for bulk collection; capable models for analysis and synthesis.
- **Right-size findings.** Match output volume to the question asked — 3 confirmed bugs beat a 15-item enumeration.

## Things to avoid
- **Don't regenerate AI-smell prose after a hook fires.** Em-dashes, excessive bold, Label:fragment rows — cut them before resending, not cosmetically patch around them.
- **Don't perform self-criticism.** A formatted RCA or numbered pattern list under pushback reads as track-covering. Run the check it names first, then report the result.
- **Don't fan out without a cost estimate.** Before launching a token-expensive workflow when the user has a stated quota, offer an explicit go/no-go with the estimated spend.

## Open questions / known gaps
- Prose hygiene corrections don't stick within a session — the same tells reappear after a single correction cycle, suggesting the hook fires but the rewrite is cosmetic.
