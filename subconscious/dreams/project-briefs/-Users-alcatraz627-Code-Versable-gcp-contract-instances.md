## What this project is about
GCP contract/instance management for Versable, worked in complex multi-task sessions with parallel review panels, mechanical fixes, and demo-deadline context switches.

## Things to do (or keep doing)
- Route mechanical documentation and fix passes to lower-tier sub-agents; reserve main/opus capacity for ideation and judgment calls
- When orchestrating parallel review panels, include a maximally adversarial seat that challenges the product category itself, not just surface quality
- Track sub-agent completion against output files on disk — idle notifications alone are unreliable as completion signals
- Honor explicit parking directives ("park it as it is") immediately, without attempting cleanup or closure

## Things to avoid
- Don't show a task list without first verifying it belongs to the current session — a wrong-session list provokes strong user frustration
- Don't scope a review panel to the current session's presentation goal; the user expects real usability gaps and product-level critique
- Don't re-dispatch work when a stale idle notification arrives from an already-stopped agent; distinguish stop + idle crossing from live completion
- Don't continue optimizing a work stream after a same-day demo deadline is revealed mid-session — treat it as a full scope and priority reset

## Open questions / known gaps
- No established protocol for verifying task-list session scope before rendering; agent must derive this defensively each time
- Batching fix items by type for offline code waves is preferred but underdocumented — clarify grouping heuristics if the pattern recurs
