## What this project is about
A data transformation and pipeline tooling project with customer-facing document generation. Work spans backend pipelines, UI surfaces, and professional output artifacts.

## Things to do (or keep doing)
- Always verify UI and server changes by navigating to the actual URL and exercising the primary flow before declaring done — inspection is not verification
- Scan `git log` before implementing any new mechanism (ID storage, config value, version change) — recent commits frequently already solve it
- Complete all prerequisite research and user Q&A before launching multi-agent debate or consensus workflows — running expensive orchestration over incomplete inputs wastes the budget twice

## Things to avoid
- Never place a period immediately after a file path in output — Ghostty auto-links paths and swallows the trailing period, breaking the link; follow every path with a space, word, or comma
- Don't default to hardware/throughput metrics when the user asks for workflow augmentations — surface user-facing utility improvements, not infra numbers
- Strip AI-register phrasing from any customer-facing document: no "Good news first:", no reflexive apologies like "That is on us", no leading-question closers

## Open questions / known gaps
- Recurring tension between what the agent thinks "working" means vs. what the user requires — runtime exercise at the real URL is the bar, not a passing compile or test collect
