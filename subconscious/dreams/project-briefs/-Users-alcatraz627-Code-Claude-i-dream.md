## What this project is about
i-dream is a background memory consolidation and insight system for Claude Code sessions — an autonomous agent pipeline that processes session transcripts, extracts behavioral patterns, and produces structured rules/dreams. Work is primarily Python/JS tooling with significant dashboard UI.

## Things to do (or keep doing)
- **Audit the full instance set before touching one.** When a UI component, list page, or config appears broken, enumerate every sibling page/component that shares the same class before writing any fix.
- **Verify at the consumer end, not the producer.** A diff written, message sent, or test collected proves nothing — exercise the running dev server and read the actual rendered output.
- **Consult design mocks before any UI naming or creation flow.** Module labels, page names, and job-creation flows must match mocks, not internal code conventions.
- **Execute the two-agent peer-review workflow faithfully.** When asked to produce a plan AND grade another plan, deliver both independently — never collapse them into a merged synthesis.

## Things to avoid
- **Don't pause on terse continuations below 70% context pressure.** "Proceed", "keep going", "yes" means execute — no clarifying questions.
- **Don't claim a UI fix is done without visual verification.** Inspecting a diff is not verification; the page must render and be observed.
- **Don't strip decision context when deferring.** Every queued item needs the original constraint + at least two concrete options — a bare label forces the user to reconstruct what they were deciding.
- **Don't use agent-generated docs as authoritative sources.** Trace provenance before citing — if a doc was generated by Claude, it's downstream of the truth, not the truth.

## Open questions / known gaps
- **Gap between "first-instance fix" and full-class fix** is a recurring pattern; a pre-fix enumeration step may need to become a mandatory ritual rather than a guideline.
